### 3.1. 【P1-1】テストフレームワークの導入

*   **目的:** `pytest` を導入し、データベース操作の主要なロジックに対する単体テストを構築する。これにより、今後のリファクタリングが既存機能を破壊しないことを保証する。
*   **想定工数:** 8時間

#### 3.1.1. 詳細修正手順

1.  **`pytest` と関連ライブラリの追加:**
    *   `requirements.txt` に `pytest`, `pytest-flask`, `pytest-cov` を追加し、`pip install -r requirements.txt` を実行します。
2.  **テスト用設定の追加:**
    *   `config.py` に `TestingConfig` を追加します。データベースはインメモリのSQLiteを使用するように構成します。
3.  **テストの基本構成作成:**
    *   `tests/conftest.py` を作成し、テスト用のFlaskアプリケーションインスタンス (`app`) とテストクライアント (`client`) を提供する `fixture` を定義します。
4.  **`DatabaseManager` のテスト作成:**
    *   `tests/database/` ディレクトリを作成します。
    *   `tests/database/test_manager.py` を作成し、`DatabaseManager` のCRUD処理（例: `save_pokemon`, `get_pokemon_by_id` など）に対するテストケースを記述します。テスト実行ごとにデータベースが初期化されるようにします。

#### 3.1.2. コード例

**`config.py` (修正後)**
```python
class TestingConfig(Config):
    TESTING = True
    SQLALCHEMY_DATABASE_URI = 'sqlite:///:memory:' # インメモリDBを使用
    WTF_CSRF_ENABLED = False
```

**`tests/conftest.py` (新規作成)**
```python
import pytest
from app import create_app
from src.database.manager import DatabaseManager

@pytest.fixture(scope='module')
def app():
    """テスト用のFlaskアプリケーションインスタンスを作成"""
    app = create_app('testing')
    with app.app_context():
        # ここでテスト用のDB初期化処理などを行う
        DatabaseManager.create_all_tables()
        yield app
        # テスト後のクリーンアップ処理
        DatabaseManager.drop_all_tables()

@pytest.fixture
def client(app):
    """テスト用のクライアントを返す"""
    return app.test_client()
```

**`tests/database/test_manager.py` (新規作成)**
```python
from src.database.manager import DatabaseManager

def test_save_and_get_pokemon(app):
    """ポケモンの保存と取得が正しく行えるかをテスト"""
    with app.app_context():
        # 準備
        pokemon_data = {"id": 1, "name": "フシギダネ", ...}
        DatabaseManager.save_pokemon(pokemon_data)

        # 実行
        retrieved = DatabaseManager.get_pokemon_by_id(1)

        # 検証
        assert retrieved is not None
        assert retrieved['name'] == "フシギダネ"
```

#### 3.1.3. 影響範囲

*   新規ファイル作成が主であり、既存のアプリケーションコードへの直接的な影響はありません。
*   `config.py` と `app.py` にテスト用設定を読み込むための軽微な修正が必要です。

#### 3.1.4. テスト方法

*   プロジェクトルートで `pytest` コマンドを実行し、すべてのテストがパスすることを確認します。
*   `pytest --cov=src` を実行し、`DatabaseManager` のカバレッジが向上していることを確認します。

#### 3.1.5. リスクと対策

*   **リスク:** `DatabaseManager` がグローバルな状態に依存している場合、テストの分離が難しい可能性があります。
*   **対策:** `conftest.py` の `fixture` を活用し、テストごとにクリーンなアプリケーションコンテキストとデータベースが提供されるように設計します。

## 実行結果レポート

### 実施サマリー

計画書に基づき、`pytest`を用いたテスト環境の構築を実施した。
インメモリSQLiteデータベースをテストごとにセットアップし、マスターデータを投入するfixtureを整備。
`DatabaseManager`のテスト容易性を向上させるためのリファクタリングを行い、CRUD処理に対する最初の単体テストを作成・成功させた。

### 修正ファイル一覧

*   `requirements.txt`: `pytest-flask`, `pytest-cov`を追加。
*   `config.py`: `TestingConfig`を追加。
*   `app.py`: `create_app`がテスト構成を受け取れるように修正。
*   `pytest.ini`: `pythonpath`を設定し、インポート問題を解決するために新規作成。
*   `src/database/manager.py`: 外部からDB接続を注入できるよう`__init__`等を修正。
*   `tests/conftest.py`: テスト用のDBセットアップ(スキーマ作成、データ投入)を行うfixtureを実装。
*   `tests/database/test_manager.py`: `DatabaseManager`のテストケースを新規作成。
*   `tests/test_ai_predictor.py`: 既存テストの非推奨な`sys.path`操作を削除し、インポート文を修正。

### 直面した問題と解決策

1.  **`pytest`コマンドが見つからない:**
    *   **問題:** `pip`でインストールしたスクリプトにパスが通っておらず、`pytest`コマンドが実行できなかった。
    *   **解決策:** `python -m pytest`として、Pythonモジュールとして実行することで解決した。

2.  **`ImportError` (相対インポートエラー):**
    *   **問題:** 既存のテストコード(`test_ai_predictor.py`)が、`pytest`のテスト収集メカニズムと相性の悪いインポート方法を用いていた。
    *   **解決策:** `pytest.ini`を作成して`pythonpath = .`と設定。さらに問題のテストコードから`sys.path`操作を削除し、`src`からの絶対インポートに修正した。

3.  **`OperationalError: no such table`:**
    *   **問題:** テスト実行時に`DatabaseManager`が、テスト用に準備されたDB接続とは別の、空のインメモリDBに接続していた。
    *   **解決策:** `DatabaseManager`の`__init__`を修正し、外部からDB接続オブジェクトを注入（Dependency Injection）できるようにした。テストコード側では、`conftest.py`で準備した接続を`DatabaseManager`に渡すようにした。

4.  **`OperationalError: no such column` / `KeyError`:**
    *   **問題:** テストコード内のデータ（カラム名）が、実際のDBスキーマと一致していなかった。
    *   **解決策:** スキーマファイル(`trained_pokemons.sql`)を確認し、テストコード内のカラム名を`hp_ev`→`ev_hp`のように正式名称に修正した。
