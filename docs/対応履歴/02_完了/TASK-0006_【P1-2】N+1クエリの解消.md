### 3.2. 【P1-2】N+1クエリの解消

*   **目的:** `_get_party_members` と `get_all_parties` 内で発生しているN+1クエリを `JOIN` を用いた一括取得に修正し、APIレスポンスタイムを改善する。
*   **想定工数:** 6時間

#### 3.2.1. 詳細修正手順

1.  **現状の特定:** `_get_party_members` がループ内でポケモンデータを1件ずつ取得していることを確認します。
2.  **クエリの修正:**
    *   `get_all_parties` 関数を修正します。
    *   まずパーティのリストを取得します。
    *   次に、取得したパーティのIDリストを元に、`party_members` テーブルと `pokemons` テーブルを `JOIN` し、必要なポケモンデータを一度のクエリで取得します。
    *   Python側で、取得したポケモンデータをパーティごとに紐付けます。

#### 3.2.2. コード例 (`src/database/manager.py` 内を想定)

**修正前**
```python
def get_all_parties(self):
    parties = self.db.execute("SELECT * FROM parties").fetchall()
    result = []
    for party in parties:
        party_dict = dict(party)
        party_dict['members'] = self._get_party_members(party['id']) # ループ内でクエリ発行
        result.append(party_dict)
    return result

def _get_party_members(self, party_id):
    member_ids = self.db.execute("SELECT pokemon_id FROM party_members WHERE party_id = ?", (party_id,)).fetchall()
    members = []
    for row in member_ids:
        pokemon = self.get_pokemon_by_id(row['pokemon_id']) # N+1問題
        members.append(pokemon)
    return members
```

**修正後**
```python
def get_all_parties_with_members(self):
    """JOINを使用してパーティとメンバーを一括取得する"""
    sql = """
        SELECT
            p.id as party_id,
            p.name as party_name,
            pm.pokemon_id,
            pk.name as pokemon_name,
            pk.type1,
            pk.type2
        FROM parties p
        JOIN party_members pm ON p.id = pm.party_id
        JOIN pokemons pk ON pm.pokemon_id = pk.id
        ORDER BY p.id
    """
    rows = self.db.execute(sql).fetchall()

    parties = {}
    for row in rows:
        party_id = row['party_id']
        if party_id not in parties:
            parties[party_id] = {
                "id": party_id,
                "name": row['party_name'],
                "members": []
            }
        parties[party_id]['members'].append({
            "id": row['pokemon_id'],
            "name": row['pokemon_name'],
            "type1": row['type1'],
            "type2": row['type2']
        })
    return list(parties.values())
```

#### 3.2.4. テスト方法

*   【P1-1】で作成したテスト基盤上で、`get_all_parties_with_members` の単体テストを作成します。
*   複数のパーティとポケモンを登録し、返されるデータ構造が期待通りであること、かつすべてのメンバーが含まれていることを検証します。
*   SQLのログを出力し、発行されるクエリが1回になっていることを確認します。

#### 3.2.5. リスクと対策

*   **リスク:** 複雑な `JOIN` により、意図しないデータが返されたり、パフォーマンスが逆に悪化する可能性があります。
*   **対策:** まずは単純な `JOIN` から始め、テストで結果を検証しながら徐々にクエリを改良します。`EXPLAIN QUERY PLAN` を使用してクエリの実行計画を確認します。
