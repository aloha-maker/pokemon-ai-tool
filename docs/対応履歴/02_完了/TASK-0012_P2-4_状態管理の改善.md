## 作業タイトル
P2-4: グローバル変数による状態管理の改善

### 現状
- `src/state.py` に定義されたグローバル変数（`video_tasks`, `ocr_thread` など）を用いて、スレッド間の状態共有が行われている。
- グローバルな状態は追跡が困難で、競合状態（Race Condition）を引き起こす可能性があり、テストを不可能にしている。
- `ui/routes.py` の `simulations = {}` のように、ユーザーセッションに紐づくデータがシングルトンの辞書で管理されており、複数ユーザーの同時アクセスに対応できない。

### 修正内容
- `src/state.py` を廃止し、グローバル変数に依存しない堅牢な状態管理機構を導入する。
- アプリケーションの状態をカプセル化する専用のクラス（例: `AppState`）を設計・導入する。
- ユーザセッションに紐づくデータは、Flask-Sessionなどの拡張機能を用いて適切に管理する。

### 手順
1. `AppState` クラスを新規に作成する。`src/state.py` にある変数と関連するロックをすべてこのクラスのインスタンス変数として移動させる。
2. `app.py` の `create_app` ファクトリ内で `AppState` のインスタンスを生成する。
3. Flaskのアプリケーションコンテキスト (`g` オブジェクト) やDIコンテナを利用して、`AppState` のインスタンスを各コンポーネント（APIルート、SocketIOハンドラ）で利用できるようにする。
4. これまで `from src.state import ...` としていたすべてのモジュールをリファクタリングし、コンテキストから `AppState` インスタンスを取得して利用するように変更する。
5. `src/state.py` ファイルを削除する。
6. （別タスク）Flask-Sessionを導入し、`simulations` のようなセッションデータをグローバル変数からセッション管理に移行する。

### 影響範囲
- `src/state.py` (削除)
- `app.py`
- `src/sockets/handlers.py`
- `src/workers/` 配下のファイル
- `src/routes/` 配下でグローバル状態を参照しているファイル

### テスト方法
- 状態管理クラス (`AppState`) の単体テストを作成する。
- リアルタイム解析機能や動画解析機能など、これまでグローバル状態に依存していた機能の結合テストを実行し、リファクタリング前と変わらず動作することを確認する。

### 工数
大

### リスク
- アプリケーションの実行中状態を管理する中核部分の変更であり、誤るとリアルタイム処理が停止するなどの致命的な不具合に繋がる。
- 競合状態に関する問題は再現性が低く、テストで見逃される可能性がある。
