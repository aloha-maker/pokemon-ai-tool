P0-2: 設定と秘匿情報の管理

  現状
  データベースパスやTesseractのパスが絶対パスでハードコードされている。SECRET_KEYのような秘匿情報が管理されておらず、開発/本番の環境分離も行われていない。

  修正内容
   1. python-dotenv を導入し、.env ファイルで環境変数と秘匿情報を管理する。
   2. プロジェクトルートに config.py を作成し、環境（開発/本番）ごとの設定をクラスとして定義する。
   3. app.py を修正し、環境変数 FLASK_ENV に基づいて適切な設定を読み込むようにする。
   4. コード内のすべてのハードコードされたパスや設定値を、Flaskの current_app.config から取得するように変更する。

  手順
   1. ライブラリ導入: pip install python-dotenv を実行し、pip freeze > requirements.txt で requirements.txt を更新する。
   2. `.gitignore` の更新: .gitignore ファイルに .env を追加し、秘匿情報がGitリポジトリにコミットされないようにする。
   3. 設定ファイルの作成:
       * .env.example を作成:

   1         FLASK_APP=app.py
   2         FLASK_ENV=development
   3         SECRET_KEY="ここに強力なシークレットキーを設定"
   4         DATABASE_URL="sqlite:///data/pokemon_ai.db"
   5         TESSERACT_PATH="C:/Program Files/Tesseract-OCR/tesseract.exe"
       * 上記をコピーして .env を作成し、ローカル環境の値を設定する。
       * config.py をプロジェクトルートに作成:

    1         # config.py
    2         import os
    3         from dotenv import load_dotenv
    4 
    5         load_dotenv()
    6         basedir = os.path.abspath(os.path.dirname(__file__))
    7 
    8         class Config:
    9             SECRET_KEY = os.environ.get('SECRET_KEY')
   10             DATABASE_URL = os.environ.get('DATABASE_URL') or \
   11                 'sqlite:///' + os.path.join(basedir, 'data', 'pokemon_ai.db')
   12             TESSERACT_PATH = os.environ.get('TESSERACT_PATH')
   13             # ... 他の共通設定
   14 
   15         class DevelopmentConfig(Config):
   16             DEBUG = True
   17 
   18         class ProductionConfig(Config):
   19             DEBUG = False
   20 
   21         config = {
   22             'development': DevelopmentConfig,
   23             'production': ProductionConfig,
   24             'default': DevelopmentConfig
   25         }
   4. `app.py` の修正:
       * 修正前:

   1         # app.config.from_mapping(...)
   2         # socketio.run(app, debug=True, ...)
       * 修正後:

    1         from config import config
    2         # ...
    3 
    4         def create_app():
    5             app = Flask(__name__)
    6             # 環境変数から設定を読み込む
    7             config_name = os.getenv('FLASK_ENV', 'default')
    8             app.config.from_object(config[config_name])
    9 
   10             # ... (Blueprint登録など)
   11             return app, socketio
   12 
   13         if __name__ == '__main__':
   14             app, socketio = create_app()
   15             socketio.run(app) # debugフラグなどはconfigから自動で読み込まれる
   5. 既存コードの修正: ハードコードされたパスを current_app.config から読み込むように変更する。
       * 例 (`src/database/manager.py`):
           * 修正前: self.db_path = os.path.join(..., 'data', 'pokemon_ai.db')
           * 修正後: from flask import current_app; self.db_path = current_app.config['DATABASE_URL'].replace('sqlite:///', '')

  影響範囲
   - app.py
   - src/database/manager.py
   - src/core/ocr/config.py (このファイルは最終的に多くの設定を config.py に移管し、内容を大幅に削減できる)
   - その他、パスをハードコードしているすべてのファイル

  テスト方法
   1. .env で FLASK_ENV=development を設定し、python app.py で起動。デバッグモードで動作することを確認。
   2. データベース接続やOCR処理など、パスの変更が影響する機能が正常に動作することを確認。
   3. .env で FLASK_ENV=production に変更して起動し、デバッグモードが無効になっていることを確認。

  工数
  約4〜6時間（影響範囲が広く、各ファイルの修正と動作確認を慎重に行う必要があるため）

  リスク
   - リスク: 中。多数のファイルのパス参照を変更するため、修正漏れがあると一部の機能が動作しなくなる。
   - 対策: grep やIDEの検索機能で C:\ や .db などの文字列を検索し、ハードコードされたパスを網羅的に洗い出して修正する。
