# F-04 対戦中アクションサジェスト 実装タスクリスト

## 1. 基盤整備とリファクタリング (Foundation & Refactoring)
- [ ] `src/core/ocr.py` に存在する重複した `GameStateParser` クラスを修正し、コードのクリーンアップを行う。
- [ ] `app.py` から `src/main.py` のようなリアルタイム処理ループ（画面キャプチャ → OCR → AI予測）を管理するためのバックグラウンドプロセス管理機構を設計・実装する。

## 2. OCRパイプラインの強化とリアルタイム連携 (OCR & Real-time Integration)
- [ ] `app.py` 起動時に、バックグラウンドで画面キャプチャとOCRを定期的に実行するスレッドまたはプロセスを開始する。
    - `ScreenCapturer` と `GameStateParser` を使用して、最新の盤面情報をメモリ上に保持する。
- [ ] `app.py` のSocketIOイベント (`get_suggestion`) を修正し、ダミーデータではなく、バックグラウンドプロセスが保持する最新の盤面情報を利用してAIに問い合わせるようにする。
- [ ] OCRで読み取った結果（ポケモン名、技リストなど）をフロントエンドに送信し、正しく認識できているかデバッグ表示する機能を設ける。

## 3. AIモデルの高度化 (AI Model Enhancement)
- [ ] `src/ai/predictor.py` の `ActionAIModel` をリファクタリングする。
    - `predict_action` メソッドが、HP、状態異常、天候などの詳細な盤面情報を受け取れるように引数を拡張する。
- [ ] `predict_action` の予測ロジックを強化する。
    - [ ] 自分のHPが低い場合に交代を推奨するロジックを追加する。
    - [ ] 相手のポケモンに対して有利な控えポケモンがいる場合、交代を提案するロジックを実装する (`TODO` の箇所）。
    - [ ] 補助技（例: ステルスロック、つるぎのまい）の使用を判断するロジックの基礎を設ける。

## 4. フロントエンド連携 (Frontend Integration)
- [ ] `static/main.js` のSocketIOクライアントが、定期的に盤面情報をサーバーに送信し、AIからの提案を待つように実装する。
- [ ] サーバーから受け取った推奨アクション（技選択/交代）と理由を、`templates/index.html` の指定された領域に分かりやすく表示する処理を実装する。

## 5. テストと調整 (Testing & Refinement)
- [ ] `roi_config.json` の座標を実際のゲーム画面に合わせて微調整し、OCR認識精度を向上させる。
- [ ] 複数の異なる対戦シナリオ（有利、不利、膠着状態など）を用意し、AIの提案が妥当であるかを手動でテスト・評価する。
- [ ] エンドツーエンドのテストを実施し、画面キャプチャからUI表示までの一連の流れが5秒以内に完了することを確認する（要件定義の性能要件）。
