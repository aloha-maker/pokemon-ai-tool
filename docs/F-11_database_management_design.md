# F-11 詳細設計書: データベース管理機能

## 1. 概要

本機能は、アプリケーション全体で使用される永続データの管理を一元的に担う。SQLiteデータベースへの接続、データの読み書き、スキーマの定義など、データベースに関連する全ての操作をカプセル化する。

## 2. 責任範囲

- SQLiteデータベースファイルへの接続と切断を管理する。
- ポケモン図鑑、技、パーティ、対戦履歴などのデータを格納するためのテーブルスキーマを定義する (`schema.sql`)。
- アプリケーションの他モジュール（AI機能、Web APIなど）からの要求に応じて、CRUD（作成、読み取り、更新、削除）操作を実行するインターフェースを提供する。
- データベース操作をコンテキストマネージャ (`with` 文) で安全に実行できるようにする。

## 3. 主要コンポーネント

### 3.1. `DatabaseManager` クラス (`src/database/manager.py`)

データベース操作を抽象化し、単一のインターフェースを提供するクラス。

#### 主要メソッド

- **`__init__(self, db_path=None)`**
  - **機能:** `DatabaseManager` を初期化する。
  - **処理:** データベースファイルのパスを決定する。デフォルトでは `data/pokemon_ai.db` となる。

- **`__enter__(self)` / `__exit__(self, ...)`**
  - **機能:** `with` 文による安全な接続管理を可能にする。
  - **処理:** `__enter__` で `connect()` を呼び出し、`__exit__` で `close()` を呼び出す。

- **`connect(self)` / `close(self)`**
  - **機能:** データベースへの接続と切断を管理する。

- **`get_pokemon_by_name(self, name: str) -> dict | None`**
  - **機能:** ポケモン名（日本語名または英語名）をキーに、`pokemons` テーブルから詳細データを取得する。

- **`get_move_by_name(self, name: str) -> dict | None`**
  - **機能:** 技名をキーに、`moves` テーブルからデータを取得する。

- **`add_battle_log(self, log_data: dict) -> int`**
  - **機能:** 手動で入力された対戦結果を `battle_logs` テーブルに保存する。
  - **処理:** 受け取った辞書から必要な情報を抽出し、JSON形式にシリアライズしてデータベースに挿入する。

- **`add_battle_log_from_video(self, video_task_id: str, turn_data: dict) -> int`**
  - **機能:** 動画解析機能から渡されたターンデータを `battle_logs` テーブルに保存する。
  - **処理:** `video_task_id` と共に、ターンデータをJSON形式で保存する。

- **`get_battle_history(self, limit: int = 50) -> list[dict]`**
  - **機能:** `battle_logs` テーブルから最新の対戦履歴を指定された件数だけ取得する。

- **`get_battle_log_by_id(self, log_id: int) -> dict | None`**
  - **機能:** `battle_logs` テーブルから特定のIDを持つ単一の対戦履歴を取得する。

- **`get_battle_stats(self) -> dict`**
  - **機能:** `battle_logs` テーブルの全レコードを集計し、総対戦数、勝利数、勝率などの統計データを計算する。

### 3.2. データベーススキーマ (`data/schema.sql`)

データベースのテーブル構造を定義するSQLファイル。

- **`pokemons` テーブル:** ポケモンの図鑑データ（ID, 名前, タイプ, 種族値など）。
- **`moves` テーブル:** 技のデータ（ID, 名前, タイプ, 威力, 命中率など）。
- **`parties` テーブル:** ユーザーが構築したパーティのメタ情報。
- **`party_members` テーブル:** 特定のパーティに属するポケモンの詳細情報（持ち物, 技構成など）。
- **`battle_logs` テーブル:** 対戦一回ごとの履歴データ。勝敗、相手パーティ、ターンごとの詳細なログ（JSON形式）などを保存。
- **`analysis_results` テーブル:** AIによる対戦ログの分析結果（勝因、敗因など）を保存。

## 4. データフロー

1. **入力:**
   - 他のモジュールからのデータ操作要求（例: `get_pokemon_by_name("ピカチュウ")`, `add_battle_log({...})`）。

2. **処理:**
   - `DatabaseManager` のメソッドが呼び出される。
   - メソッドはSQLクエリを生成し、`sqlite3` ライブラリを通じてデータベースに対して実行する。
   - `INSERT`, `UPDATE` などの書き込み処理後は、`self.conn.commit()` を呼び出してトランザクションを確定する。

3. **出力:**
   - `SELECT` クエリの場合: データベースから取得したデータ（辞書または辞書のリスト）。
   - `INSERT` クエリの場合: 新しく作成されたレコードのID (`lastrowid`)。

## 5. 依存関係

- **外部ライブラリ:**
  - `sqlite3`: Python標準のSQLiteインターフェース。

- **内部モジュール:**
  - なし (本モジュールはアプリケーションの最下層に位置し、他モジュールに依存しない)。

## 6. 初期設定

- データベースファイル (`pokemon_ai.db`) が存在しない場合、`scripts/setup_database.py` スクリプトを実行することで、`schema.sql` と `master_data` 内のCSVファイルに基づいて初期化される。
