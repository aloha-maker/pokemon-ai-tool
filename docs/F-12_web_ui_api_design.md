# F-12 詳細設計書: Web UI / API機能

## 1. 概要

本機能は、FlaskとFlask-SocketIOを用いて、アプリケーション全体のフロントエンドUIとバックエンドAPIを提供する。ユーザーはWebブラウザを通じてリアルタイムのゲーム解析、AIによる提案、対戦履歴の閲覧などを行うことができる。

## 2. 責任範囲

- **Web UI:**
  - `index.html` をルートページとして提供する。
  - リアルタイム解析の状況（OCR結果、キャプチャ画像）、AIの行動予測などをWebSocketを通じて動的に更新・表示する。
  - ユーザーがパーティ選出やパーティ構築支援機能を利用するためのインターフェースを提供する。
- **REST API:**
  - 各AI機能（勝率予測、パーティ構築）を呼び出すためのHTTPエンドポイントを提供する。
  - 対戦履歴の追加や取得を行うためのエンドポイントを提供する。
  - 動画のアップロードと解析結果の取得を行うためのエンドポイントを提供する。
- **WebSocket API:**
  - リアルタイム画面解析の開始・停止を制御する。
  - OCR結果やAIの行動提案をクライアントにリアルタイムでプッシュ通知する。

## 3. 主要コンポーネント

### 3.1. Flaskアプリケーション (`app.py`)

Webサーバーの本体。ルーティング、リクエスト処理、テンプレートのレンダリングを行う。

#### REST API エンドポイント

- **`GET /`**
  - **機能:** メインページ (`index.html`) を表示する。
- **`POST /predict`**
  - **機能:** 勝率予測AIを呼び出す。`WinRatePredictor` に処理を委譲する。
- **`POST /generate-party`**
  - **機能:** パーティ構築AIを呼び出す。`PartyGenerator` に処理を委譲する。
- **`GET /api/windows`**
  - **機能:** 現在デスクトップで開かれているウィンドウのタイトルリストを取得する。リアルタイム解析の対象を選択するために使用。
- **`POST /api/history/add`**
  - **機能:** 対戦履歴を手動で追加する。`DatabaseManager` に処理を委譲する。
- **`GET /api/history`**
  - **機能:** 対戦履歴と統計データを取得する。`DatabaseManager` に処理を委譲する。
- **`POST /api/videos/upload`**
  - **機能:** 対戦動画ファイルをアップロードし、バックグラウンドでの解析タスクを開始する。
- **`GET /api/videos/status/<task_id>`**
  - **機能:** 動画解析タスクの進捗状況を問い合わせる。
- **`GET /api/videos/result/<log_id>`**
  - **機能:** 解析が完了した対戦ログの詳細を取得する。

### 3.2. Flask-SocketIO (`app.py`)

クライアントとサーバー間の双方向リアルタイム通信を管理する。

#### WebSocket イベント

- **`connect` / `disconnect`**
  - **機能:** クライアントの接続・切断をハンドリングする。
- **`start_analysis`**
  - **機能:** クライアントからの要求に基づき、バックグラウンドで `ocr_and_suggestion_thread` を開始する。
- **`stop_analysis`**
  - **機能:** リアルタイム解析スレッドを停止する。
- **`get_suggestion`**
  - **機能:** 最新の盤面情報に基づいて、AIの行動提案を要求する。
- **`ocr_update` (サーバーからクライアントへ)**
  - **機能:** OCRで読み取った最新の盤面情報をクライアントに送信する。
- **`suggestion_update` (サーバーからクライアントへ)**
  - **機能:** AIが生成した行動提案をクライアントに送信する。
- **`analysis_started` / `analysis_stopped` (サーバーからクライアントへ)**
  - **機能:** 解析スreadの状態変化をクライアントに通知する。

### 3.3. フロントエンド (`templates/index.html`, `static/`)

ユーザーが直接操作するインターフェース。

- **`index.html`:** アプリケーションの骨格となるHTML。各機能エリア（リアルタイム解析、パーティ選出など）のレイアウトを定義。
- **`main.js`:** SocketIOのイベントハンドリング、APIへのリクエスト送信（`fetch`）、DOMの動的更新など、クライアントサイドのロジックを記述。
- **`style.css`:** アプリケーションの見た目を定義。

## 4. データフロー

- **リアルタイム解析:**
  1. ユーザーがUIでウィンドウを選択し、「解析開始」ボタンを押す。
  2. `start_analysis` イベントがサーバーに送信される。
  3. サーバーで `ocr_and_suggestion_thread` が起動する。
  4. スレッドは定期的に画面をキャプチャ→OCRを実行し、`ocr_update` イベントで結果をクライアントに送信する。
  5. ユーザーが「提案取得」ボタンを押すと `get_suggestion` イベントが飛び、サーバーは `ActionAIModel` で推論し、`suggestion_update` イベントで結果を返す。
- **API利用:**
  1. ユーザーがUI上でパーティ情報を入力し、「予測」ボタンを押す。
  2. `main.js` が `/predict` エンドポイントに `POST` リクエストを送信する。
  3. `app.py` がリクエストを処理し、AI機能のクラスを呼び出す。
  4. AI機能が結果を返し、`app.py` はそれをJSON形式でレスポンスとして返す。
  5. `main.js` がレスポンスを受け取り、結果を画面に表示する。

## 5. 依存関係

- **外部ライブラリ:**
  - `Flask`: Webフレームワーク。
  - `Flask-SocketIO`: WebSocket通信。
  - `Flask-Executor`: バックグラウンドタスクの実行。
  - `pygetwindow`: ウィンドウリストの取得。
- **内部モジュール:**
  - アプリケーションのほぼ全ての機能（`ScreenCapturer`, `GameStateParser`, 各種AIモデル, `DatabaseManager`）を必要に応じて呼び出す、最上位の統合レイヤー。
