# データベース改善タスクリスト

## 1. 背景

現在のデータベース関連の実装には、分析レポートで指摘されている通り、以下の2つの主要な問題が存在します。

1.  **データアクセス層の欠如**: 各機能が直接データベース（`sqlite3`）を呼び出しており、コードの再利用性が低く、将来のメンテナンスが困難になっています。
2.  **スキーマの不整合**: `app.py` が `data/schema.sql` とは異なる独自のテーブル (`match_history`) を作成・利用しており、データベースの定義が一元管理されていません。

これらの問題を解決し、より堅牢でメンテナンス性の高いアプリケーションにするため、以下のタスクを実行します。

---

## 2. 改善タスク一覧

### タスク1: データベーススキーマの統一

**目的:** データベースの定義を `data/schema.sql` に一本化し、アプリケーション全体で共通のテーブル定義を利用するようにします。

-   [ ] **`app.py` の修正:**
    -   [ ] `app.py` 内の `init_db` 関数と、`match_history` テーブルを作成するロジックを完全に削除します。
    -   [ ] 対戦履歴を扱うAPIエンドポイント (`/api/history/add`, `/api/history`) を修正し、`match_history` テーブルの代わりに `data/schema.sql` で定義されている `battle_logs` テーブルを使用するようにSQLクエリを書き換えます。
        -   カラム名も `battle_logs` テーブルの定義に合わせる必要があります。（例: `my_selection` -> `my_party_id` など）

---

### タスク2: データアクセス層 (Managerクラス) の実装

**目的:** データベースへの直接的なアクセスを `DatabaseManager` クラスに集約し、他のモジュールからの呼び出しをシンプルにします。

-   [ ] **`DatabaseManager` クラスの作成 (`src/database/manager.py`):**
    -   [ ] データベースへの接続・切断を管理するクラスを作成します。
    -   [ ] アプリケーション内の各所から必要とされる、以下のようなデータ取得・更新メソッドを実装します。
        -   `get_pokemon_by_name(name)`: ポケモン名から詳細データを取得
        -   `get_move_by_name(name)`: 技名から詳細データを取得
        -   `add_battle_log(log_data)`: 対戦履歴を `battle_logs` テーブルに追加
        -   `get_battle_history(limit=50)`: 対戦履歴の一覧を取得
        -   `get_battle_stats()`: 勝率などの統計データを計算

-   [ ] **既存コードのリファクタリング:**
    -   **目的:** `sqlite3` を直接呼び出している箇所を、すべて新しい `DatabaseManager` のメソッド呼び出しに置き換えます。
    -   [ ] **対象ファイル:**
        -   `src/ai/predictor.py`
        -   `src/ai/win_rate_predictor.py`
        -   `src/ai/party_generator.py`
        -   `app.py` (タスク1で修正する対戦履歴APIなど)
