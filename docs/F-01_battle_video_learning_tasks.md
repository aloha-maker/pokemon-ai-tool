# F-01 対戦動画学習機能 実装タスクリスト

## 1. 背景・目的

現在のAIによる行動提案は、ルールベースのロジックに限定されている。人間の実際の対戦データ（特に、どのような状況でどの技を選択したか）を学習させることで、より精度の高く、人間らしい思考に近い行動提案AIを実現する。

本機能では、ユーザーが録画した対戦動画をシステムにアップロードし、その動画から一連のバトルログ（誰が何をしたか）を自動で抽出・保存する仕組みを構築する。そして、蓄積されたデータをAIの改善に活用する。

---

## 2. 機能要件

-   **動画アップロード**: ユーザーは、フロントエンドの専用画面から対戦動画ファイル（mp4, mov等）をアップロードできる。
-   **非同期処理**: 動画の解析には時間がかかるため、アップロード後はバックグラウンドで非同期に処理を実行する。
-   **データ抽出**: システムは、動画をフレーム単位で解析し、既存のOCR機能を活用して各ターンの盤面情報（ポケモン、HP、技リストなど）と実行された行動を抽出する。
-   **データ保存**: 抽出した一連のターン情報を、対戦全体のログとしてデータベース (`battle_logs` テーブル) に保存する。
-   **進捗確認**: ユーザーは、フロントエンドで動画解析の処理状況（待機中, 処理中, 完了, エラー）を確認できる。
-   **結果閲覧**: 解析が完了した動画のログを、フロントエンドでターンごとに閲覧できる。

---

## 3. 実装タスク一覧

### タスク1: バックエンド - 動画処理基盤の構築

**目的:** アップロードされた動画を非同期で処理し、フレームを抽出する基盤を構築する。

-   [ ] **APIエンドポイントの作成:**
    -   [ ] `/api/videos/upload` (POST): 動画ファイルを受け取り、一意のIDを割り当てて保存する。解析タスクをキューに追加し、タスクIDを即座にクライアントに返す。
    -   [ ] `/api/videos/status/<task_id>` (GET): 指定されたタスクIDの処理状況を返す。
    -   [ ] `/api/videos/result/<log_id>` (GET): 解析が完了した `battle_logs` のIDを指定し、詳細なターンごとのデータを返す。
-   [ ] **非同期タスクキューの導入:**
    -   [ ] `Celery` や `Flask-Executor` などを導入し、重い動画解析処理をバックグラウンドで実行できるようにする。
-   [ ] **動画解析モジュールの作成 (`src/core/video_processor.py`):**
    -   [ ] `OpenCV` を使用して動画ファイルを読み込み、フレームを一つずつ取り出す。
    -   [ ] フレーム間の差分を計算し、画面に大きな変化があったフレーム（＝行動選択、ポケモン交代などが発生した可能性が高いフレーム）を特定する。
    -   [ ] 特定したフレームを `GameStateParser` に渡し、盤面情報をOCRで読み取る。
    -   [ ] 複数のフレームから読み取った情報を統合し、1ターン分の行動ログ（誰が、誰に、何をしたか）を生成するロジックを実装する。

### タスク2: データベース - ログ構造の定義と保存

**目的:** ターンごとの詳細な情報を格納できるよう、ログのデータ構造を定義し、保存処理を実装する。

-   [x] **`battle_logs.battle_data` のJSONスキーマ定義:**
    -   [x] ターンごとの情報を格納するためのJSON構造を明確に定義する。 (`docs/battle_log_schema.json`)
-   [x] **`DatabaseManager` の拡張:**
    -   [x] `add_battle_log_from_video(video_id, turn_data)` のような、動画解析結果を `battle_logs` に保存するための新しいメソッドを追加する。

### タスク3: フロントエンド - UIの構築

**目的:** ユーザーが動画をアップロードし、結果を確認するための画面を構築する。

-   [x] **動画アップロード画面の作成:**
    -   [x] ファイル選択ボタンとアップロードボタンを配置したフォームを作成する。
    -   [x] アップロード中は進捗バーを表示する。
-   [x] **解析状況一覧画面の作成:**
    -   [x] アップロードした動画（タスク）の一覧と、それぞれの処理状況を表示する。
    -   [x] 定期的にAPIをポーリングして状況を更新する。
-   [x] **解析結果表示画面の作成:**
    -   [x] 完了したログを選択すると、ターンごとの盤面のスナップショット画像と、抽出されたテキスト情報を表示する。

### タスク4: AI - 収集データを用いた学習

**目的:** 蓄積された対戦ログを活用し、AIの予測モデルを改善する。

-   [ ] **統計分析モジュールの作成 (`src/ai/log_analyzer.py`):**
    -   [ ] `battle_logs` テーブルから全データを読み込み、基本的な統計情報を計算する。
        -   特定のポケモンが使用する技の頻度
        -   特定の対面（例: ミライドン vs コライドン）で選択されやすい行動
        -   テラスタルの使用タイミング
-   [ ] **ルールベースAIの改善:**
    -   [ ] `ActionAIModel` を修正し、上記の統計情報を判断材料に加える。
        -   例: 相手のこのポケモンは70%の確率でこの技を使ってくる、という情報を加味して交代の判断を行う。
-   [ ] **(将来展望) 機械学習モデルの導入:**
    -   [ ] 蓄積した `(盤面情報, 正解行動)` のペアを教師データとして、`PyTorch` や `TensorFlow` を用いて行動選択モデルを学習させる。
