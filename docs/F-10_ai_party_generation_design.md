# F-10 詳細設計書: AIパーティ構築支援機能

## 1. 概要

本機能は、ユーザーが指定した「戦術コンセプト」と「使用可能なポケモンのリスト」に基づき、バランスの取れた対戦用パーティ（6体）をAIが提案することを目的とする。パーティ構築の初期段階を支援する。

## 2. 責任範囲

- ユーザーが入力した「戦術コンセプト」（テキスト）と「使用可能なポケモン名」（リスト）を受け取る。
- `DatabaseManager` を通じて、使用可能なポケモンそれぞれの詳細データを取得する。
- 戦術コンセプトを解釈し、パーティに求められる役割（例: 高速アタッカー、物理受け、特殊受け、起点作りなど）を定義する。
- 各役割に対して、使用可能なポケモンの中から最も適したポケモンを割り当てる。
- 最終的に選出された6体のリストと、その選出理由を整形して返す。

## 3. 主要コンポーネント

### 3.1. `PartyGenerator` クラス (`src/ai/party_generator.py`)

パーティ構築のロジックをカプセル化するクラス。

#### 主要メソッド

- **`__init__(self)`**
  - **機能:** `PartyGenerator` のインスタンスを初期化する。
  - **処理:**
    1. `DatabaseManager` のインスタンスを生成し、データベースへの接続を準備する。

- **`generate(self, available_pokemon_names: list[str], concept: str) -> dict`**
  - **機能:** コンセプトに合ったパーティを生成する。
  - **引数:**
    - `available_pokemon_names` (list[str]): ユーザーが使用できるポケモンの名前リスト。
    - `concept` (str): 構築したいパーティの戦術コンセプト（例: 「対面構築」「受けループ」「雨パ」など）。
  - **戻り値:** 提案するパーティ構成と、そのコンセプトを説明する辞書。
  - **処理:**
    1. `DatabaseManager` を使って、`available_pokemon_names` の全ポケモンの詳細データを取得する。
    2. `_interpret_concept()` を呼び出し、入力された `concept` テキストからパーティに要求される役割のリストを生成する。
    3. `_find_best_pokemon_for_role()` を繰り返し呼び出し、各役割に最適なポケモンを割り当てていく。
    4. タイプのバランス（弱点の偏りなど）を `_check_balance()` で評価し、必要であれば一部のポケモンを入れ替える調整を行う。
    5. 最終的なパーティ構成（6体）と、構築意図を説明するテキストを生成し、辞書として返す。

- **`_interpret_concept(self, concept: str) -> list[str]`**
  - **機能:** テキストで記述されたコンセプトを、具体的なポケモンの役割リストに変換する。
  - **戻り値:** 役割名のリスト (例: `['fast_attacker', 'physical_wall', 'special_wall', ...]`)
  - **処理:**
    1. （現状の簡易ロジック）キーワードマッチングを行う。例えば `concept` に「受け」が含まれていれば `['physical_wall', 'special_wall']` を必須要件とする。
    2. （将来的には）自然言語処理モデルを用いて、より柔軟にコンセプトを解釈する。

- **`_find_best_pokemon_for_role(self, role: str, pokemon_pool: list[dict]) -> dict`**
  - **機能:** 指定された役割に最も適したポケモンを、候補の中から見つけ出す。
  - **引数:**
    - `role` (str): 求める役割（例: `fast_attacker`）。
    - `pokemon_pool` (list[dict]): ポケモンの候補リスト。
  - **戻り値:** 最も適したポケモンのデータ辞書。
  - **処理:**
    1. 役割に応じて、評価する種族値の指標を決定する。（例: `fast_attacker` なら `speed` と `attack`/`sp_attack` を重視）。
    2. `pokemon_pool` 内の各ポケモンを評価指標に基づいてスコアリングし、最高スコアのポケモンを選択する。

- **`_check_balance(self, party: list[dict]) -> bool`**
  - **機能:** 構築されたパーティのタイプバランスを評価する。
  - **戻り値:** バランスが良い場合は `True`、悪い場合は `False`。
  - **処理:**
    1. パーティ全体の弱点をリストアップする。
    2. 特定のタイプ（例: `ice`, `ground`）の弱点が3体以上に集中している場合、バランスが悪いと判断し `False` を返す。

## 4. データフロー

1. **入力:**
   - 使用可能なポケモン名のリスト (`list[str]`)
   - 戦術コンセプト (`str`)
   - (Web UIの `/generate-party` エンドポイント経由でJSONとして渡される)

2. **処理:**
   - `app.py` がリクエストを受け取り、`PartyGenerator` をインスタンス化して `generate()` を呼び出す。
   - `PartyGenerator` が `DatabaseManager` を利用してポケモンデータを取得し、コンセプト解釈、役割への割り当て、バランス調整を経てパーティを構築する。

3. **出力:**
   - 提案するパーティ（ポケモン6体のリスト）と構築意図を含む辞書 (`dict`)。
   - この辞書はJSONとしてクライアントに返される。
